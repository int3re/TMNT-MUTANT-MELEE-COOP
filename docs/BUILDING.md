# Сборка из исходников

[Документация](README.md) · [Как это устроено](ARCHITECTURE.md) · [История версий](CHANGELOG.md)

**Русский** · [English](en/BUILDING.md)

## Что нужно

- **Windows** и **Visual Studio** с инструментами C++ (x86).
- **CMake 3.20** или новее (подойдёт тот, что идёт с Visual Studio).
- **Python 3** — только для инструментов. Манифесту релиза и лаборатории хватает стандартной библиотеки;
  `tools/re/mmre.py` нужен пакет `capstone`, `tools/launcher_fonts.py` — `fontTools` и `brotli`,
  `tools/launcher_icon.py` — `Pillow`, `tools/glyph_four.py` — `Pillow` и `numpy`.

Всё собирается под **Win32**: `ztmnt.exe` — 32-битный процесс, и всё, что в него попадает, тоже
32-битное. Если настроить CMake на другую платформу, он остановится с ошибкой. После сборки
`tools/check_x86.cmake` смотрит заголовок `meleenet.asi` через `dumpbin`: если файл не x86, сборка
считается неудачной.

## Что берётся со стороны

| Что | Где сборка это ищет | Если этого нет |
|---|---|---|
| **ENet** (UDP) | `../tmnt2003-netplay/third_party/enet` — дерево [TMNT-2003-COOP](https://github.com/int3re/TMNT-2003-COOP), клонированное с `--recursive` рядом с этим, в папку `tmnt2003-netplay`. Другое место: `-DTMNT1_DIR=<путь>` | сборка не начинается |
| **Ultimate ASI Loader**, 32-битный | `../tmnt2003-netplay/third_party/ultimate-asi-loader/bin/Win32/Release/dinput8.dll` (его собирает там `tools/build_asi_loader.ps1`). Любая 32-битная сборка [загрузчика](https://github.com/ThirteenAG/Ultimate-ASI-Loader): `-DUAL_DLL=<файл>` | в результате нет `dinput8.dll`, и лаунчер не собирается |
| **Steamworks SDK** | `../steamworks_sdk_165/sdk`. Другое место: `-DSTEAMWORKS_SDK_DIR=<путь к sdk>` | мод собирается без Steam: игра по адресу и лабораторная замена Steam |

Путь к загрузчику от `TMNT1_DIR` не зависит: если дерево TMNT-2003-COOP лежит в другом месте, задайте и
`-DUAL_DLL`.

MinHook лежит в репозитории (`third_party/minhook`). Steamworks SDK принадлежит Valve и в репозиторий не
входит никогда.

Шрифты и значок лаунчера тоже лежат в репозитории (`src/launcher/assets`; рядом со шрифтами — их лицензии
и описание). Шрифты делает `tools/launcher_fonts.py`, значок рисует `tools/launcher_icon.py`. Без файла
шрифта заголовков `DelaGothicOne-Regular.ttf` сборка проходит, а заголовки лаунчер рисует системным
шрифтом.

Цифра 4 для шрифта меню самой игры — `src/mod/glyph4.h` — тоже лежит в репозитории. Её рисует
`tools/glyph_four.py`; для сборки скрипт не нужен, он нужен, только чтобы нарисовать глиф заново.

## Сборка

Этот репозиторий и дерево TMNT-2003-COOP — в соседние папки:

```bash
git clone https://github.com/int3re/TMNT-MUTANT-MELEE-COOP
```

```bash
git clone --recursive https://github.com/int3re/TMNT-2003-COOP tmnt2003-netplay
```

Загрузчик (один раз):

```bash
powershell -ExecutionPolicy Bypass -File tmnt2003-netplay/tools/build_asi_loader.ps1
```

Конфигурация и сборка — из папки `TMNT-MUTANT-MELEE-COOP`:

```bash
cmake -S . -B build -A Win32
```

```bash
cmake --build build --config Release
```

При конфигурации CMake пишет, нашёлся ли Steamworks SDK (`Steam: ON` или `Steam: OFF`) и какие версии
лаунчера и мода пойдут в сборку.

Результат — в `build/dist/Release`:

| Файл | Что это |
|---|---|
| `meleenet-launcher.exe` | лаунчер с модом внутри: тот файл, который идёт в релиз |
| `meleenet.asi`, `meleenet.ini`, `meleenet-README.md` | мод, его настройки, его короткое описание |
| `dinput8.dll` | Ultimate ASI Loader |
| `steam_api.dll` | библиотека Steam, если SDK нашёлся |

Только мод:

```bash
cmake --build build --config Release --target meleenet
```

Только лаунчер (мод соберётся тоже: он лежит внутри лаунчера):

```bash
cmake --build build --config Release --target meleenet_launcher
```

Версии и `dist/release.json` записаны в зависимости конфигурации: после их изменения CMake при следующей
сборке сам проходит конфигурацию заново, и пакет внутри лаунчера получает новые номера.

Библиотека времени выполнения C подключается статически: распространяемый пакет Visual C++ игроку не
нужен.

То же самое одной командой делает `tools/build.ps1`. Он берёт CMake из `PATH`, а если его там нет — тот,
что идёт с самой новой установленной Visual Studio; настраивает сборку, если она ещё не настроена или
задан `-Configure`; собирает цель `-Target` (без него — `meleenet`) и показывает только ошибки,
предупреждения своего кода и список готовых файлов:

```bash
powershell -ExecutionPolicy Bypass -File tools/build.ps1 -Configure -Target meleenet_launcher
```

## Версии

| Что | Где |
|---|---|
| версия мода | `src/common/version.h`, `MELEENET_VERSION` и `MELEENET_VERSION_W` |
| сетевой протокол | `src/common/protocol.h`, `kVersion` — меняется при любом изменении раскладки пакетов, каналов или смысла полей; там же, в комментарии, его история |
| версия лаунчера | `src/launcher/launcher.h`, `kLauncherVersion` — меняется, когда меняется сам лаунчер |
| какая версия мода на каком протоколе | `src/launcher/core.cpp`, таблица `kProtocols` — для установленной версии, которую описание релиза не называет |
| что релиз говорит о себе | `dist/release.json`: версия, протокол, дата, заголовок (не больше 40 знаков), от одной до четырёх заметок (каждая не больше 110 знаков), протоколы прежних версий |

## Релиз

Релиз — это два файла под тегом `v<версия>`: `meleenet-launcher.exe` и `meleenet-latest.json`.

1. Заполните `dist/release.json` и версии **до** сборки: `release.json` встраивается в лаунчер, из него
   лаунчер берёт заметки о той версии мода, что лежит у него внутри. Если `release.json` написан не для
   той версии, что стоит в `version.h`, конфигурация об этом предупредит.
2. Соберите.
3. Сделайте манифест:

   ```bash
   python tools/release_manifest.py build/dist/Release/meleenet-launcher.exe build/dist/Release/meleenet-latest.json
   ```

   В манифесте — то, что записано в `release.json`, плюс имя, размер и SHA-256 файла лаунчера и версия
   лаунчера. Скрипт останавливается, если `release.json` расходится с исходниками в версии или в
   протоколе, если заголовок или заметки длиннее положенного и если лаунчер собран не из этих исходников.
4. Опубликуйте оба файла как файлы релиза GitHub `v<версия>`. Лаунчер запрашивает
   `<репозиторий>/releases/latest/download/meleenet-latest.json`, а файл лаунчера берёт из
   `<репозиторий>/releases/download/v<версия>/`.

Адрес репозитория записан в `src/launcher/launcher.h` (`kRepoUrl`): форк, которому нужны свои обновления,
меняет его там. С пустым `kRepoUrl` лаунчер в сеть не ходит.

## Лаборатория

`tools/lab` запускает копии игры с модом, ни разу их не показывая: окно стоит за пределами экрана и никогда
не берёт фокус, полный экран запрещён, звук копии выключен, ролики не играются, прогон заканчивается сам
на заданном игровом кадре.

Нужны ваша собственная игра в папке `TMNT Mutant Melee` рядом с репозиторием (игра в репозиторий не
входит) и собранный мод в `build/dist/Release`. Тестовые копии — папки `test-mm`, `test-mmb`, `test-mmc`,
`test-mmd` рядом с репозиторием — лаборатория делает сама (`lab.py`): файлы игры в них — жёсткие ссылки,
свои у каждой копии только настройки, привязки и сохранение (`tmnt.ini`, `tmntwire.hks`, `tmnt.sv`).

| Скрипт | Что он делает |
|---|---|
| `run_one.py <кадры> "<сценарий>" [ключ=значение …]` | одна копия со сценарием нажатий; `--shots 300,600` сохраняет картинки этих кадров, `--sheet <файл.png>` собирает их на один лист |
| `run_twice.py <кадры> "<сценарий>"` | две копии одновременно играют один и тот же сценарий: одинаковы ли их покадровые журналы? Кадры сценария считаются от главного меню: мод входит в него заново, сбросив часы и случайные числа. `--pre-b "<сценарий>"` даёт второй копии другую предысторию до этого момента |
| `diverge.py` | после `run_twice.py`: где копии разошлись и, если прогон шёл с `rng_trace`, первое случайное число, которое отличается, с адресами тех, кто его взял |
| `run_net.py <кадры> [--players N] [--p1 "<сценарий>"] [--p2 …] [--via enet\|mock]` | сетевая игра двух–четырёх копий на одном компьютере, по адресу или через замену Steam; каждая копия играет свой сценарий за своего игрока; журналы всех копий сравниваются кадр за кадром |
| `run_page.py <кадры> [--players N] [--via addr\|mock]` | весь путь через страницу СЕТЕВАЯ ИГРА: копии стартуют обычными играми, проходят меню, одна создаёт игру, остальные входят, хост начинает — и каждая игра запускает себя заново уже в сетевой игре |
| `run_door.py <кадры> [--via addr\|mock]` | игрок входит в идущую сессию: копии 1 и 2 через страницу сети собираются в сессию и начинают бой; тогда запускается копия 3, проходит своё меню и стучится к хосту. Она ждёт у двери, пока первые двое не выйдут из боя, после чего все три игры запускают себя заново в сессию троих; `<кадры>` — сколько кадров играет эта последняя сессия, её покадровые журналы должны совпасть |

Например, одна копия: 1500 кадров, пять нажатий Enter, картинка кадра 1300 на листе:

```bash
python tools/lab/run_one.py 1500 "200 enter;400 enter;600 enter;800 enter;1000 enter" --shots 1300 --sheet menu.png
```

Три копии в одной сетевой игре, 1200 кадров:

```bash
python tools/lab/run_net.py 1200 --players 3
```

Сценарий — это строки вида `<кадр>[-<кадр>] [pN.]<кнопка>[+<кнопка>…]`, в командной строке через `;`:
`420 enter`, `600-640 right+attack`, `700 p2.jump`. Кнопки: `up`, `down`, `left`, `right`, `attack`, `alt`,
`jump`, `action`, `special`, `block`, `esc`, `enter`, `back`, `start`, `space`, `f11`. Нажатие без диапазона
длится четыре кадра. Кадры — игровые, а не кадры экрана.

Покадровый журнал — `meleenet-sim.log` в папке копии: строка на игровой кадр с его номером, режимом
игры, числом взятых случайных чисел, отпечатком состояния, отпечатком геймпадов и временем игры.

Переключатели лаборатории — это раздел `[debug]` в `meleenet.ini`; каждый описан в `src/mod/config.h`:
сеть с потерями и обрывами, застывший кадр, трасса случайных чисел, снимки кадров и другое.
`ключ=значение` в командной строке попадает туда же. В `run_one.py` и `run_net.py` ключ с именем раздела
идёт в этот раздел: `net.delay=3` — в `[net]`, `video.mode=window` — в `[video]`; в `run_net.py`
`p2:net_loss=20` достаётся только второй копии.

Переключатели, которые появились в версии 0.2.0:

| Ключ `[debug]` | Что он делает |
|---|---|
| `draw_every = N` | рисуется только каждый N-й игровой кадр, остальные проигрываются без картинки |
| `draw_cost = N` | каждая картинка стоит на N мс больше: медленная видеокарта |
| `desync_at = N` | на игровом кадре N эта копия берёт одно лишнее случайное число: её игра расходится с остальными |
| `story_open = 1` | все этапы «Истории» открыты |
| `ko_enemies = N`, `ko_hero = N`, `ko_partners = N` | на игровом кадре N эти бойцы матча «Истории» — враги, герой, партнёры — теряют всё здоровье |
| `epoch_boot = 1` | вместе с `epoch = 1`: заново проигрывается весь запуск игры, а не только вход в главное меню — как при старте сессии |
| `autoquit_players = N` | вместе с `page = 1`: `autoquit_frame` считается только в сессии, где не меньше N игроков (сессия, которая впускает игрока, начинается заново) |
| `net_outage_once = 1` | обрыв связи `net_outage` случается только в первой сессии прогона |

Например, медленная вторая копия в сетевой игре двоих:

```bash
python tools/lab/run_net.py 3000 --p1 "<сценарий>" --p2 "<сценарий>" "p2:draw_cost=30"
```

**Прежняя версия против новой.** В `run_net.py` запись `pN:asi=<файл>` даёт копии N другую сборку
`meleenet.asi`:

```bash
python tools/lab/run_net.py 2500 --p1 "<сценарий>" --p2 "<сценарий>" "p2:asi=<прежний meleenet.asi>"
```

Так проверена совместимость 0.1.1 с 0.1.0: хост — 0.1.1, гость — 0.1.0, 2500 кадров с боем, журналы
совпали.

Чего лаборатория проверить не может — так это настоящее окно игры перед игроком (клавиатуру, настоящую
мышь, набор адреса, Alt+Tab) и настоящий Steam. Это проверяется игрой.

## Инструменты разбора игры

`tools/re` — инструменты, с которыми написаны [заметки](../re/notes.md). Они читают вашу собственную копию
игры; папка `re/dump/`, где лежат копия exe и его декомпиляция, в репозиторий не попадает.

| Инструмент | Что он делает |
|---|---|
| `mmre.py` | чтение `ztmnt.exe`: дизассемблер, функция вокруг адреса, ссылки на адрес, строки, байты, классы с их таблицами (RTTI), импорт. Читает `re/dump/ztmnt.exe` — копию exe, которую вы кладёте туда сами; свои имена адресов — в `re/names.txt` |
| `ghidra/ExportDecomp.java` | пост-скрипт Ghidra: декомпилированный C всех функций в один файл (аргумент — путь к нему) |
| `dc.py` | чтение этого файла, `re/dump/decomp.c`: функция по адресу, поиск по тексту (`-g`), кто упоминает адрес (`-c`) |
| `arc.py` | архив игры (`archive.arc` и `archive.dat`): список файлов, файл на экран или на диск. Игру ищет в папке `TMNT Mutant Melee` рядом с репозиторием |
| `tex.py` | текстуры игры в PNG; `--game "<папка игры>"` — другая папка игры |

## Лаунчер без окна

| Команда | Что она делает |
|---|---|
| `meleenet-launcher.exe --shot <экран> <файл.png>` | экран лаунчера в виде картинки: `ready`, `checking`, `update`, `downloading`, `selfupdate`, `install`, `nogame`, `offline`, `blocked`, `running`, `problem`, `settings`, `graphics`, `sound` (это вкладка СЕТЬ: в коде у неё осталось имя из общего кода лаунчеров), `controls`, `controls2`, `capture`. `--scale N` — масштаб картинки, `--accent 0..3` — цвет повязки |
| `meleenet-launcher.exe /install "<папка игры>" /quiet` | ставит мод в папку игры без окна; код возврата 0 или 2. `/package <файл лаунчера>` — ставит мод из другого файла лаунчера |
| `meleenet-launcher.exe /uninstall "<папка игры>" /quiet` | убирает мод |
| `meleenet-launcher.exe --drive "<шаги>" --pick <папка игры> --settings <ini> --cache <папка> --out <журнал>` | лаунчер под управлением сценария, окно не показывается. Шаги через `;`: `wait:<мс>`, `until:<экран>:<мс>`, `click:<имя>`, `type:<текст>`, `keydown:<vk>:<scan>:<ext>`, `rdown`, `xdown:<n>`, `state`, `shot:<png>`, `quit`. `--repo <адрес>` — страница репозитория, поданная из другого места |
| `meleenet-launcher.exe --check --out <журнал>` | спрашивает у GitHub самый новый релиз и записывает, что пришло |
| `meleenet-launcher.exe --where --out <журнал>` | записывает, где лаунчер нашёл бы игру и что в ней стоит |

Обновление можно проверить без настоящего релиза. `tools/lab/newer_release.py <лаунчер> <папка> <версия мода>
<версия лаунчера>` делает из собранного лаунчера «более новый релиз» — копию, чья опись пакета называет другие
версии, и `meleenet-latest.json` к ней; `tools/lab/serve_release.py <порт> <папка>` отдаёт эту папку так, как
GitHub отдаёт страницу релиза. Лаунчеру адрес подмены даёт `--repo http://127.0.0.1:<порт>/r`. Копию лаунчера
кладите в отдельную папку: обновляясь, он заменяет свой файл. Со своим `--settings` лаунчер игру сам не ищет:
первым шагом сценария укажите её (`until:nogame:8000;click:primary` с `--pick`).

## Чего нет в репозитории

- Файлов игры и Steamworks SDK.
- Того, что достаётся из игры при разборе: папки `re/dump/` (копия exe, декомпиляция, проект Ghidra). Сами
  заметки (`re/notes.md`) и инструменты (`tools/re`) в репозитории есть.
- Снимков лаборатории (`re/shots/`) и прежних сборок мода (`re/old/`).
