# TMNT Mutant Melee (PC) — заметки по разбору `ztmnt.exe`

Мод: `meleenet` (meleenet.asi / meleenet.ini / meleenet.log).
Игра лежит рядом с репозиторием, в папке `TMNT Mutant Melee` (русская версия; тестовые копии на жёстких
ссылках там же: `test-mm`, `test-mmb`, `test-mmc`, `test-mmd` — их делает `tools/lab/lab.py`).

## 1. Файл

- `ztmnt.exe` 1 753 088 байт, sha256 `585a5809…dce2`, сборка «Nov 22 2004», база 0x400000.
  **Не упакован и не защищён**: секции `.text` 0x401000–0x55B000, `_rwcseg`, `.rdata` 0x55C000–0x583000,
  `.data` 0x583000–0x688774, `_rwdseg`. Есть RTTI (имена классов `Tt…`), строки отладочного меню.
- Движок: свой (Konami Hawaii) на RenderWare 3.5, **Direct3D 8**, DirectInput 8, DirectSound, Bink.
- Импорты: `DINPUT8.dll` (DirectInput8Create) — под этим именем кладётся Ultimate ASI Loader;
  `d3d8.dll` (Direct3DCreate8, слот 0x55C228), `DSOUND.dll` #1, `binkw32.dll`, USER32, KERNEL32.
- Данные: `archive.arc` (указатель) + `archive.dat`; тексты — `TMNT_LANGUAGE.CSV` внутри архива; интерфейс —
  скрипты `ui/scripts/UI_*.txt` (элементы `HC_…`). Звук: `soundPC/MUSIC.MCP`, `sfx_all.thp`, `VCLIP.BKT`.
- Настройки игры: `tmnt.ini` (subsystem, fullscreen, width, height, depth, brightness, contrast, toonshading,
  dynamicshadows, particlepercent), `tmntwire.hks` (привязки, см. §4), сохранение `tmnt.sv`.
- Ключи командной строки (разработчиков): `-noui -level <имя> -players N -frag -lastman -teamlms -teamfrag
  -protect -survive -lightning -tagteam -khill -kaway -bomb -balloon -mecha -crystal -unlocked -quickgame
  -longgame -nokeyboard -nosound -nomusic -noinitfile -fullscreen -width -height -depth -filedebug -errorlog
  -exitafterload -memstats -perfbars`.

Инструменты: `tools/re/mmre.py` (dis / func / xref / str / dw / hex / rtti / vt / imp по файлу),
`tools/re/dc.py` (чтение `re/dump/decomp.c` — Ghidra, все функции: `dc.py <addr>`, `-g <regex>`, `-c <addr>`),
`tools/re/ghidra/ExportDecomp.java`. `re/dump` в git не идёт.

## 2. Главный цикл (sys_main.cpp)

- WinMain 0x401040 → init 0x403D40 → цикл 0x405E10: `{ 0x405370; кадр 0x405C00(1) }`.
- Кадр 0x405C00(char update): смена режима + `mode->Enter()` (вызов по адресу **0x405CA3**:
  `mov eax,[ecx]; call [eax+4]` — мод заменяет на свой call), `mode->Update()` (vtable +8), рисование
  0x4051E0 (`mode->Draw()` +0xC), отложенный выход из режима (+0x10) с затемнением, затем «системное
  обновление» **0x408CB0**: прошлое состояние геймпадов, сообщения окна, часы **0x4062F0**, чтение устройств
  **0x408580**.
- Текущий режим `[0x5AF0F8]`, запрошенный `[0x5AF0FC]`, выход из цикла `byte [0x5AEFD0]`.
- Режимы — объекты, созданные один раз в 0x405430; указатели на них в таблице 0x5B08B4…0x5B0954 (41 шт.,
  размеры в `game.h: kModeSizes`). Объекты помнят курсоры / выборы между заходами.
- Порядок от запуска: TtMemCardBootCheckMode → TtMemCardLoadMode → TtBootMode (логотипы) → TtAttractMode
  (ролик) → TtTitleScreenMode («нажми ввод») → **TtGameStartMode (главное меню)** → …
  Рукопашный бой: TtPlayerSelectMode → TtLevelSelectMode → TtMeleeOptionsMode → TtMeleeGameLoadMode →
  TtMeleeGameIntroMode → TtMeleeGameMode → (пауза: Esc, 3-й пункт = выход) TtReturnToUIMode → главное меню.
  История: TtAdventureSelectMode → BackStory → GameSelect → Explanation → Load → Intro → MeleeGameMode.
- **Второй поток**: «Background Graphics Thread» (цикл 0x4109C0) во время загрузки уровня (основной поток
  внутри Update режима загрузки, 0x411800) крутит `кадр(0)`: рисует экран загрузки и вызывает системное
  обновление. Число таких проходов зависит от реального времени → мод не считает их игровыми кадрами
  (`sim.cpp: is_tick`). Игра создаёт устройство D3D без MULTITHREADED при двух потоках → мод добавляет флаг
  (иначе редкие падения в драйвере на загрузке).
- Ролик Bink — цикл внутри одного вызова 0x408E50(const char* name) со своим системным обновлением.

## 3. Время и случайные числа

- Часы 0x4062F0: реальное время кадра × Speed Scale (`[0x5B0838]` = 0.85), не меньше 0.01 с (предел 100 fps),
  сглаживание, Delta `[0x5AEFDC]`, Ave `[0x5AEFD8]`, Elapsed `[0x5AEFE0]`, счётчик `[0x5AEFE4]`.
  Мод: ровно 0.85/60 с на игровой кадр и свой темп 60 fps.
- Секундомеры реального времени: 0x406290 (старт, QPC) / 0x4062A0 (прошло секунд, в ST0): затемнение между
  режимами (0.35 с), ожидания загрузчика, статистика. Мод переводит их на игровые кадры.
- Основной генератор — RenderWare RpRandom 0x500D80 (сид 0x500E10; состояние в RwGlobals `[0x682C84]` +
  `[0x683224]`), 71 функция. Сид берётся из Elapsed Time×1000 при входе в выбор героев (0x44F860).
  `rand()` CRT (0x4E144F, состояние 0x5A7080) — только звук (высота тона, выбор реплики).
- **Реплики героев**: правила игры спрашивают «звучит ли реплика» (команда звука 0x1E, поток
  `[0x68274C]`+0x80 ≠ 2) и по ответу тянут RpRandom (0x442A90, 0x442630, выбор героя и др.). Ответ зависит
  от звуковой карты → мод отвечает по игровым часам: длительность = размер клипа в `VCLIP.BKT`
  (22050 Гц, 16 бит, моно; заголовок {размер, событий 675, клипов 3645, смещ. событий, смещ. клипов};
  событие {u16 первый, u8 шанс, u8 число}; клип {начало, конец}). См. `sound.cpp`.
- Проверено в лаборатории: две свежие копии с одним скриптом идентичны с первого кадра (5200 кадров, бой);
  копия с «историей» (уже сыгранный бой) расходится с свежей примерно через 500 кадров боя (ИИ) —
  **поэтому сессия начинается с перезапуска игры**, а не «на лету».

## 4. Ввод

- Четыре «геймпада» по 0xF4 байта с 0x5AE838: 19 float сейчас, 19 прошлого кадра (+0x4C), 19 разницы (+0x98),
  байт «подключён» +0xE8. Значения: 0 стик X, 1 стик Y, 2 special, 3 block, 4 attack, 5 alt, 6 jump,
  7 action, 8 Esc (пауза в бою), 9 «подтвердить» (Enter; у джойстика — attack в меню), 10 «назад» (Esc в
  меню), 11 start, 12 пробел, 14/15/16 — меню разработчиков (F1), 17 — F11.
- `byte [0x5B0880]` = «управление меню»: клавиатура читается как стрелки / Enter / Esc, а не по привязкам.
- Клавиатура → геймпад: 0x4068F0(pad, player); джойстик: 0x408290. Состояние клавиатуры DirectInput:
  256 байт с 0x5B09A0. Мышь: мод ставит в этот массив коды 0xF0–0xF4 (ЛКМ, ПКМ, СКМ, боковые) перед 0x4068F0.
- `tmntwire.hks`: 100 записей по 0x30 байт: {номер геймпада, устройство (0 клавиатура, n джойстик), вверх,
  вниз, влево, вправо, attack, alt attack, action, jump, special, block} — для клавиатуры коды DIK.
  По умолчанию W S A D, N, M, H, J, пробел, B.
- Меню слушают любой подключённый геймпад (0x40A7C0 «подтвердить», 0x40A820 «назад», 0x40A720/0x40A770 влево/вправо);
  «ведущий» геймпад `[0x5B088C]` — экран загрузки («нажми ввод»).

## 5. Экран

- 0x4073D0 читает tmntwire.hks и tmnt.ini; 0x408650 создаёт окно («TMNT CLASS») и устройство RenderWare;
  0x407290 выбирает видеорежим — **всегда 640×480×16** и полный экран (`[0x5AE829]` = 1 принудительно);
  смена разрешения в игре = запись ini и перезапуск (`_execv`, 0x4017B0).
- Мод: окно своё (без рамки / обычное), устройство оконное любого размера (свой режим в конец списка
  IDirect3D8::EnumAdapterModes), `[0x5AE829]` = 0 после создания окна.
- Широкий экран — родной переключатель консолей `byte [0x5AF3D3]`: в 0x402000 вид 16:9 вместо 4:3
  (константы-операнды 0x4020B5 / 0x4020C1), 2D сжимается к центру множителем `[0x583B50]` (0.75),
  меню закрывают бока двумя полосами (0x40AB90, операнды 0x40ABC6 / 0x40ABCD / 0x40ABE1). Мод подставляет
  форму своего кадра. Камера на логику не влияет (копии 16:9 и 4:3 идентичны).
- Та же форма записана ещё в трёх числах для того, что рисует 2D-тулкит: ширина экрана текста `[0x583B54]` (1.3333,
  0x409350 — экран текста начинается с −(ширина − 1) / 2) и чёрный лист затемнения `[0x583B58]` / `[0x583B5C]` (0x40AAB0).
  Мод пишет 1 / масштаб во все три: при консольных 1.3333 на 21:9 надписи стояли мимо своих плашек.
- **Меню на весь широкий кадр** (0.1.1, `[video] menus = wide`, по умолчанию; `bars` — родные полосы): полосы 0x40AB90 не
  рисуются, а каждый скрипт экрана `UI_*.txt` по дороге к разборщику расширяется (`uiwide.cpp`, вызов из `menu.cpp hkOpen`).
  Элемент, который кончается у края раскладки (x ≤ 0 или x + w ≥ 640), доводится до края кадра по виду его текстуры:
  `wrap_uv = 1` (соты, верхняя труба) — прямоугольник и UV шире, плитка продолжается; несколько текселей, растянутых
  вширь (чёрные рамки, линии) — просто шире; кирпичные стены снизу `brick02` / `brick` и картинка загрузки `control` —
  **второй элемент рядом с зеркальной текстурой** (плиткой нельзя: у `brick02` правая четверть прозрачная — её закрывает
  пандус `brick`, а пандус не повторяется); плашки заголовков `sele_wdw`, полосы скорости `pol_chara_bg` — второй элемент
  из одного столбца текселей у края. Элементы за краем (въезжают / уезжают) сдвигаются за край кадра. Тексты, кнопки,
  портреты остаются на местах 4:3. Факты разборщика: `start_uvwh` читается `atol` (целые, отрицательные можно, отрицательная
  ширина = зеркало), `start_xywh` — `atof`; одноимённые элементы допустимы (в родных скриптах по три `PipeTop`), всё, что
  не `HC_`, рисуется само; текстура без `wrap_uv` адресуется CLAMP. Текстуры смотреть: `tools/re/tex.py <имя> --out dir`.
- Карта «Истории» рисуется кодом (TtAdventureGameSelectMode, Draw 0x4441A0): карта — один большой квадрат (0x443ED0),
  поверх четыре затемнённые полосы той же текстуры вокруг окна карты (0x443D40, доли экрана 4:3). Мод заменяет 0x443D40
  теми же полосами до краёв кадра (`video.cpp hkMapFrame`), иначе по бокам видна голая карта.
- Библиотека (TtLibraryMode) — страница 4:3 на чёрном, так и оставлена.

## 6. Сеть (meleenet)

- Сессия = игра, запущенная заново (`MELEENET_NET=host|join`, либо `[net] mode` в ini для лаборатории).
  Перед первым режимом игроки встречаются (`netplay::meet`), гость получает сохранение хоста
  (`tmnt-net.sv`, имя файла подменяется в 4 местах 0x4CA150 / 0x4CA302 / 0x4CA4C5 / 0x4CA55B).
- Быстрый старт: до первого входа в главное меню часы и секундомеры ×8, без темпа 60 fps; «нажми ввод»
  нажимает хост. Главное меню — на 150-м кадре.
- Lockstep, хост в центре: гости шлют Input, хост — Bundle со всеми геймпадами; задержка ввода 2 кадра;
  хэш состояния (RpRandom + Elapsed) раз в 60 кадров (гость может быть на кадр-два впереди: его хэш ждёт хэша хоста).
- В сессии: частицы 100 % (их число тянет RpRandom), ролики не играются.

## 7. Лаборатория

- `tools/lab/run_one.py <кадры> "<скрипт>"`, `run_twice.py` (две копии, сравнение `meleenet-sim.log`),
  `run_net.py <кадры> --p1 … --p2 …` (сессия 2–4 копий), `diverge.py` (где разошлись + трасса RpRandom), `run_page.py` (весь путь через сетевую страницу), `run_door.py` (вход в идущую игру).
- Скрипт: строки `<кадр>[-<кадр>] [pN.]<кнопка>[+…]`; кнопки: up down left right attack alt jump action
  special block esc(пауза) enter back start space.
- Окна тестовых копий вне экрана, не активируются, без звука, ролики выключены (`[debug]`).

## 8. Интерфейс игры и меню мода

- Экраны — скрипты `ui/scripts/UI_*.txt` в архиве (`tools/re/arc.py ls|cat|get`): блоки `UI_Element <имя> { … }`,
  координаты 640×480 (y снизу), `asset_name` = текстура или `$N` (строка N таблицы языка), `event = enter|exit`,
  `delay`, `duration`. **Строки файла должны кончаться `\r\n`**: разборщик (0x43A6E0) режет последнее слово только по `\r`.
  Имена с префиксом `HC_` сверяются со встроенной таблицей — свои элементы называть без него.
- Менеджер показа `[0x673548]`, синглтон скриптов `[0x5B08A0]` (список главного меню +0x10); вход списка 0x43B670,
  выход 0x43B760, поиск элемента по имени 0x438FA0 (+0x30 «выбран», +0x31 «приглушён»), «ещё движется» 0x4391B0.
- Главное меню — TtGameStartMode: Update 0x44A660 (курсор +0x1C по модулю 5, флаг ухода +0x18, таблицы имён 0x586F0C…).
  Мод (`menu.cpp`) подменяет скрипт `UI_ModeSel_PC.txt` своим (шесть кнопок из тех же картинок; файловые функции игры
  0x401A30 / 0x4026D0 / 0x401C50 / 0x401AA0) и целиком заменяет Update: страницы сети — те же шесть кнопок с другими словами.
- Таблица языка: `language/tmnt_language` (UTF-16, строки `ключ,текст`), в памяти — вектор `wchar_t*` по +8 синглтона
  `[0x5B08A4]`; строка N = N-я строка файла. Мод пишет свои тексты поверх консольных строк 165–197 (на месте, не длиннее старых).
- **Шифр русской версии**: кириллица нарисована на местах строчных латинских букв и цифр:
  а=a б=6 в=b г=f д=d е=e ж=g з=3 и,й=n к=k л=o м=m н=h о=0 п=z р=p с=c т=t у=y ф=v х=x ц=q ч=4 ш,щ=w ъ,ь=j ы=s э=3 ю=u я=r;
  заглавные латинские остаются латинскими. Цифры 4 и 6 на экране — «ч» и «б» (`gametext.cpp`).
- Прямое рисование текста: 0x40AC30(font `[0x672EC8]`, wchar*, размер, float xywh[4] (0..1, y снизу), 1, кисть `[0x5B1078]`, тень, 0xFF)
  между 0x40AA00(1) и 0x4093F0(); после своего текста сбрасывать текстуру (0x536380(1, 0)). Хук — 0x4037E0 (после Draw режима).

## 9. Лаунчер

- `src/launcher` — код лаунчера общий с модами TMNT 2 и «Суперсемейка» (установка, обновление с GitHub, вкладки настроек),
  вид свой (`view.cpp`): фон — стена меню игры (соты, светлеющие вправо, чёрные трубы, синий кирпич с пандусом), чёрные
  окна и кнопки в стальной рамке, выбранное — на бледной плашке; цвет сот и акцентов — повязка одной из четырёх черепах
  (`[launcher] accent` 0–3, по умолчанию синяя), маска этого цвета повязана рядом с названием. Значок — `tools/launcher_icon.py`.
  Адрес репозитория — `kRepoUrl` в `launcher.h` (пустой адрес = лаунчер сеть не трогает).
  Вкладки: ЛАУНЧЕР / ГРАФИКА / СЕТЬ / УПРАВЛЕНИЕ; `gameset.cpp` пишет `meleenet.ini` и запись клавиатуры в `tmntwire.hks`.
- Проверка без окна: `meleenet-launcher.exe --shot ready|install|graphics|sound|controls "<png>"`, `/install "<папка>" /quiet`,
  `/uninstall`, `--where`. Пути с пробелами в PowerShell — одной строкой аргументов с кавычками.
- Перед сборкой релиза: `dist/release.json` (версия, заметки), `src/common/version.h`, `kLauncherVersion`, таблица `kProtocols` в core.cpp.
- Релиз = два файла: `meleenet-launcher.exe` и `meleenet-latest.json` (`python tools/release_manifest.py <лаунчер> <json>`);
  лаунчер спрашивает `…/releases/latest/download/meleenet-latest.json`, скачивает названный там файл, сверяет SHA-256,
  ставит мод изнутри него и встаёт на место себя. Порядок релиза — в `docs/BUILDING.md`.
- Обновление без окна и без настоящего релиза: `tools/lab/newer_release.py <лаунчер> <папка> <версия мода> <версия лаунчера>`
  делает из собранного лаунчера «более новый релиз» (ресурсы 300 — опись пакета, 299 — заметки), `tools/lab/serve_release.py
  <порт> <папка>` отдаёт его как страница релиза GitHub; лаунчеру — `--repo http://127.0.0.1:<порт>/r --settings <ini>
  --cache <папка> --pick <папка игры> --out <журнал> --drive "…" --drive-next "…"` (шаги сценария: `until:<экран>:<мс>`,
  `click:primary`, `wait:<мс>`, `shot:<png>`, `quit`). Со своими `--settings` лаунчер игру сам не ищет: первым прогоном
  `until:nogame:8000;click:primary` с `--pick`. Копия лаунчера должна лежать в отдельной папке: он заменяет свой файл.
- Репозиторий: github.com/int3re/TMNT-MUTANT-MELEE-COOP; первый релиз — v0.1.1 (лаунчер 1.1.0). Проверено на нём: `--check`
  читает описание релиза напрямую; лаунчер 1.0.1 с `--repo <адрес репозитория>` сам взял 1.1.0 и поставил 0.1.1 поверх 0.1.0.
- Установщик оставляет `meleenet.ini` игрока. Значение по умолчанию, которое меняется между версиями, переводить в
  `package.cpp refresh_settings` (версия прежней установки — первая строка `meleenet-install.txt`): так 0.1.1 один раз
  меняет `menus = bars` из ini 0.1.0 на `wide`.
- Старая сборка против новой в одной сессии: `run_net.py … "p2:asi=<путь к старому meleenet.asi>"` (0.1.0 лежит в `re/old/`).

## 11. Версия 0.3.0: игра начинается заново без нового процесса

### 11.1 Что такое «память игры»

- Записываемые секции exe: `[0x583000, 0x68A000)` — `.data` с bss и `_rwdseg` RenderWare; образ не перемещается.
- Куча игры (sys_mem.cpp): один блок 64 МБ от `malloc` при старте (0x40BBA0), база `[0x5B10A8]`, конец `[0x5B10A4]`;
  всё состояние распределителя — заголовки блоков по 0x20 байт внутри неё (FEEDBEEF, метка, размер, соседи, свободный
  список, контрольная сумма), глобалы 0x5B10A4..0x5B10C5 и три пула STL в bss. RenderWare берёт память там же
  (таблица функций в RwEngineInit — обёртки над 0x40B5B0 / 0x40BD60 / 0x40BF90). `[0x5B10C5]` = `-usemalloc` (тогда кучи нет).
  Распределитель обнуляет выданное, но не «хвосты» (до 0x40 байт после блока) и `realloc` читает дальше старого блока —
  поэтому сохраняется всё до последнего ненулевого байта, а при возврате лишнее обнуляется.
- На куче C-библиотеки (`[0x688644]`, несериализованная) живёт только звук: таблицы голосов `[0x680A20]`, `[0x680A24]`,
  таблица банков `[0x680A28]` и три её массива буферов, записи сэмплов `[0x680A3C..44]`, буферы `[0x681FFC]`, `[0x682738]`.
- Потоки: в exe один `CreateThread` — «Background Graphics Thread» (0x4109C0), создан раз, спит на событии `[0x66E130]`,
  во время загрузки уровня крутит `кадр(0)` под большим замком `[0x5AE7BC]` (CRITICAL_SECTION на +4, лежит в куче).
  Звук и потоки музыки опрашиваются из главного цикла (0x442A90), своих потоков нет.
- Файлы: три звуковых и `archive.dat` открыты всю жизнь процесса, каждое чтение начинается с позиционирования.
  `tmnt.sv` держится открытым между кадрами в `[0x682340]` (закрытие — 0x4310E0).
- Direct3D: устройство `[0x6853A8]`, поверхности `[0x6853B0]` / `[0x6853AC]`; драйвер кэширует состояния устройства в
  `.data` (0x6832F8..0x6857F8) и пропускает «лишние» вызовы. Создание ресурсов: CreateTexture (слот 20), CreateCubeTexture
  (22), CreateVertexBuffer (23), CreateIndexBuffer (24), CreateDepthStencilSurface (26), CreateImageSurface (27),
  шейдеры (75 / 78, 87 / 90).
- DirectSound: `[0x680A1C]` (импорт по номеру, слот 0x55C008); статический буфер на сэмпл банка, дубликат на каждый
  сыгранный звук; банки 0 и 1 пересоздаются на каждый уровень (команда звука 6).

### 11.2 Мод (`rewind.cpp`, пространство имён `anew`)

- `capture()` — в перехвате входа в самый первый режим (0x405CA3, TtMemCardBootCheckMode), до его Enter: копия секций,
  использованной части кучи (~8 МБ) и звуковых блоков; все живые объекты Direct3D (321) и буферы DirectSound (79)
  получают по ссылке мода и запоминают счётчик; блок состояния устройства (`CreateStateBlock(ALL)`).
- `restore()` — в том же месте кода, когда `sim.cpp` просит «эпоху» с первого режима: ждёт, пока поток загрузки вне
  кадра; закрывает открытый поток сохранения; останавливает звуки и отпускает буферы, созданные позже; возвращает память
  (кроме 0x18 байт замка), обнуляет испачканный хвост кучи; сбрасывает семь событий; `ApplyStateBlock` и `SetRenderTarget`;
  отпускает ресурсы Direct3D и шейдеры, созданные позже; возвращает счётчики ссылок удержанных. 15–30 мс.
- Как мод узнаёт, что ресурс уничтожен: ресурсу Direct3D вешается «свидетель» — приватные данные-объект
  (`SetPrivateData(..., D3DSPD_IUNKNOWN)`), ресурс сам отпускает его при уничтожении; у звукового буфера перехвачен Release.
- **Сброс устройства в первом кадре.** Драйвер RenderWare создаёт устройство «без ожидания монитора», а первый показ
  кадра (0x541E6A..) просит ожидание и ради этого делает `Reset` (сравнивает флаг кадра с параметрами в 0x687080:
  в окне — SwapEffect 3 / 4 по `[0x687094]`, на весь экран — интервал `[0x6870B0]`). `Reset` невозможен, пока что-то
  удерживается. Мод при создании оконного устройства пишет в параметры драйвера интервал 1 — сброса нет.
  При настоящем сбросе (устройство потеряно) мод отпускает всё и возврат к старту выключается: сессии идут через
  новый процесс, как в 0.2.0. То же при `[video] mode = game`.
- Что мод сам пишет в память игры, написано до снимка (в init): глифы 4 и 6, форма кадра, настройки картинки, скрипты
  экранов. После возврата `sim.cpp` приводит в исходное своё: время секундомеров, быстрый старт, страницу меню, звуковые часы.
- Сессия на месте: `netlobby` вместо запуска процесса зовёт `netplay::begin()` (роль, путь, число игроков) →
  эпоха с первого режима → `restore()` → `netplay::meet()` — та же встреча, что в новом процессе. Гости начинают на
  1,5 с позже хоста (хост должен закрыть старый порт и открыть новый). Когда сессия кончилась и игра вернулась в
  главное меню, гость сам возвращается к старту ещё раз — уже на своём сохранении (имя файла сохранения подменяется
  только на время сессии).
- Встреча не состоялась (`meet()` вернул отказ: «ИГРОКИ НЕ ПОДКЛЮЧИЛИСЬ»): игра в этот момент стоит в самом
  начале, до чтения сохранения, — мод сразу делает её собственной игрой игрока (фаза Off, своё имя сохранения,
  `sim::hurry_boot()` — быстрый старт до главного меню). Второго возврата к старту не нужно.
- Проверка: `run_twice.py … epoch_boot=1 --pre-b "<история>"` — копия с прошлым против свежей (совпадают 4500 кадров;
  без возврата памяти расходились на первом кадре боя); сессия на месте против сессии свежих процессов — строка в
  строку (кроме счётчика случайных чисел в первой строке); `epoch_again = 3000` — возвраты подряд (память процесса
  ~280 МБ, не растёт).

### 11.3 Имена над бойцами

- Метка над бойцом человека — 0x419FF0 (thiscall, боец): стрелка цвета геймпада (таблица цветов 0x586E80) и текст
  `%iP` (в «Истории» — постоянная строка «1P» по адресу 0x55E79C) мелким шрифтом `[0x672ECC]`, прямоугольник 0.2 × 0.06

### 11.4 «История»: тренировки и вторая жизнь врага

- Загрузчик персонажей (0x42DED0) отдаёт i-го персонажа списка `[0x6753C4]` i-му бойцу. Запись «второй жизни» врага
  кладёт своего персонажа в список сразу за врагом и бойца не получает — в родных матчах она последняя, и её
  персонаж достаётся запасному бойцу за последним. С партнёрами после неё список сдвигался (падение в ИИ: у бойца нет
  модели). Мод после сборки матча ставит список в порядок «персонажи бойцов, затем вторые жизни», а после сброса
  раунда (0x454880, раскладывает записи по местам в списках) перекладывает записи друзей на их настоящих бойцов
  (0x453560).
- Тип 11 (тренировка с меха-черепахой) идёт в обычном режиме боя — партнёры допущены. Мини-игры (9, 10, 12, 13) — нет.
